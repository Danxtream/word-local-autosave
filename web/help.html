Local AutoSave · Test v0.1

This is an experimental build. Automated scheduler tests are separate from proof of saving inside Word. Use disposable documents only until the live tests below pass. Keep using normal Save for important work.

Install once

  1. Open Local AutoSave Test.app. Click 1. Install Word test add-in.
  2. Click 2. Open localhost certificate in Keychain Access. Import into the login keychain. Locate Local AutoSave localhost, double-click it, expand Trust, set only Secure Sockets Layer (SSL) to Always Trust, close the window, and authenticate if requested. The initial certificate is self-signed, valid for 90 days, limited to localhost / 127.0.0.1, and its private key stays on this Mac. Do not disable general browser or macOS security protections.
  3. Return to the test app and click 3. Enable automatic server with Word once. You can then quit the setup app. A small background watcher starts at login, starts the HTTPS server when Word opens, and stops it when Word quits. Closing a document or Word window is different from quitting Word. There are no document lists or scripts to manage.
  4. Save your open work, then quit and reopen Word yourself. Open a disposable local .docx normally through Finder. Choose Home → Add-ins → Local AutoSave. Depending on Word's layout it may be under More Add-ins → My Add-ins → Developer Add-ins. After loading, look for the Local AutoSave ribbon control on Home.
  5. The task pane must connect to Word. If it doesn't, check certificate trust and ensure automatic mode is enabled and this Mac can reach Microsoft's Office.js CDN. The app itself does not require a Microsoft 365 subscription, but Word must be licensed to edit and save documents.

Enable automatic certificate renewal once

In the setup app click 4. Enable automatic certificate renewal, review the explanation, and approve the macOS authentication prompt. This uses a private local signing certificate named Local AutoSave localhost Renewal CA. The installer restricts its user-keychain trust to SSL for localhost; do not manually set it to trust all purposes. The certificate also has critical DNS name constraints. No administrator-wide trust, online CA, or document access is required.

The local server certificates last 825 days and renew 30 days early. The helper checks on startup, at most once per day while running, and after a long sleep when Word resumes. It keeps the previous pair if renewal fails. Certificate/key updates switch atomically; the server restarts briefly after a renewal so new connections get the new certificate. Word saves run in the existing Office runtime independently of that local asset server. The signing certificate lasts approximately 100 years; replacing its trust still requires a new explicit approval. It warns before the signer can no longer issue a full-length replacement. This is automatic leaf renewal for a personal local setup, not a promise of compatibility with future macOS releases. A stolen signing key remains usable for longer; trust remains restricted to SSL for localhost.

Until this one-time setup succeeds, the old trusted certificate remains in use. Private signing keys and server keys stay in this user's application-support directory with owner-only access. The helper never changes keychain trust in the background.

First live test — original file

  1. Create a disposable file, manually save it locally as AutoSave-Test.docx, and leave it open.
  2. Open Local AutoSave, choose 1 second (Test), and switch AutoSave ON. Changing a setting saves current document edits once as well as the preference.
  3. Type a unique sentence without using Save. Wait at least five seconds. The pane should show a recent confirmed save and increasing completion count in Test diagnostics. “Active” alone means a scheduler check occurred; it does not mean a save was issued.
  4. Verify the original file independently. For a strong check, inspect its on-disk ZIP/XML while Word is still open. A tester can also duplicate the original in Finder and inspect the copy in a different viewer. Closing Word and choosing Save does not prove AutoSave worked.

Background, reopen, and independence

  1. Close the task pane, type another unique sentence, and wait. Verify the original file on disk. Reopen the pane and compare completion counters. SharedRuntime is configured; this behavior still needs testing.
  2. Edit again, switch to another Mac app before the next cycle, and check the file. Repeat at 30 seconds to leave enough time to switch apps.
  3. Close and reopen the file directly from Finder. Verify whether startup occurs and settings return. Open the pane to inspect status. If it doesn't start, manually reopen the add-in and record that as a failed automatic restart test.
  4. Open three disposable documents. Enable two with different intervals, leave the third OFF, edit all three, and verify only enabled originals are updated automatically.
  5. At 1 second, type for several minutes and check for cursor movement, lost keys, delays, dialogs, or changed selection. Compare expected text with on-disk content.
  6. Try a new unsaved document. Enabling must show an error and must never create a default-named file. Read-only / locked documents should report failures, keep the requested ON preference visible, and never create a replacement. Disable automatic server mode in the setup app and test reopening; no stale “Active” state should appear on a fresh load.

Automatic server lifecycle

A native watcher observes macOS app lifecycle events without activating Word, reading documents, or sending keystrokes. It stays idle after Word quits. A user LaunchAgent starts the watcher at login and restarts it if it exits. The server and watcher run as your user, with no administrator privileges. Status and logs are in ~/Library/Application Support/Local AutoSave Test. macOS may show the watcher under Login Items & Extensions. Disabling it there prevents automatic operation. On a very fast Word startup the add-in might request its page before HTTPS is ready; if that occurs, retry opening the pane and record it as a startup test failure.

Limits of this version

The interval is a scheduler target, not a guarantee of a physical disk write every second. In-flight operations are skipped; unchanged documents use Word's saved flag. Completion is reported only after context.sync() resolves. Word, macOS sleep, modal dialogs, or webview throttling may delay work. No crash-time or final-close save is promised.

A frozen runtime cannot repaint its own status. The pane shows the last scheduler-check time, marks prolonged gaps as unconfirmed when code is running, and rechecks on resume. No persistent ribbon “ON” indicator is used. Inspect status after waking the Mac. This cannot guarantee detection while the entire runtime is stopped.

Settings live in the document under this add-in's identity. Copies and Save As may inherit them; renamed or moved files retain embedded settings. Startup on copied files is unverified. Each current runtime checks its reported local path again before saving. Cloud URLs and unrecognized paths are refused. A synced folder exposed as a local path is indistinguishable from other local folders; the add-in itself uploads nothing.

No document contents are sent to the local server. It serves static assets only, bound to 127.0.0.1. Office.js loads from Microsoft's required CDN, so this test is not fully offline. The background watcher launches this Mac's /usr/bin/python3 only while Word is open; packaging an independent runtime or native HTTPS host is a later deployment task. The app is locally compiled and ad-hoc signed, not notarized.

Remove

Turn AutoSave OFF in each enabled document before uninstalling; that writes the OFF preference to the original file. In the setup app click Disable automatic server, then quit the setup app. This unloads and removes only ~/Library/LaunchAgents/local.autosave.word.watcher.plist. In Finder → Go → Go to Folder, open ~/Library/Containers/com.microsoft.Word/Data/Documents/wef and remove only local-autosave-test.xml. Restart Word. Do not clear other add-ins' caches. Remove Local AutoSave localhost and, if enabled, Local AutoSave localhost Renewal CA from the login keychain, and optionally delete ~/Library/Application Support/Local AutoSave Test. Keep your documents.
